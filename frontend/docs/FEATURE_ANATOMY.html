Layer by layer

DTO + validator

data/dto/user-management/user.dto.tsdata

Transport shape for a single user and the response envelopes. isUserDtoRsValid guards the raw API payload — including an ROLE_LABELS membership check — before the use case maps each item to the domain model.

import { BaseResponseRs } from '@core/network/api/base-response-rs';
import { ROLE_LABELS } from '@core/domain/roles';

export interface UserDtoRs { id: string; fullName: string; email: string; role: string; status: string; mustChangePassword: boolean; }
export interface UsersDtoRs extends BaseResponseRs<UserDtoRs[]> {}
export interface UserItemDtoRs extends BaseResponseRs<UserDtoRs> {}

export function isUserDtoRsValid(dto: UserDtoRs): boolean {
  return (
    typeof dto.id === 'string' && dto.id.length > 0 &&
    typeof dto.fullName === 'string' &&
    typeof dto.email === 'string' &&
    typeof dto.role === 'string' &&
    Object.prototype.hasOwnProperty.call(ROLE_LABELS, dto.role) &&
    (dto.status === 'active' || dto.status === 'disabled') &&
    typeof dto.mustChangePassword === 'boolean'
  );
}

Model + mapper

domain/model/user-management/user.tsdomain

User is the clean domain model — free of transport concerns. toUser maps a validated DTO to it, narrowing the loose string role and status fields to their typed union counterparts; the import of UserDtoRs is a one-way allowed cross-boundary reference.

export type UserStatus = 'active' | 'disabled';
export interface User { id: string; fullName: string; email: string; role: UserRole; status: UserStatus; mustChangePassword: boolean; }
export function toUser(dto: UserDtoRs): User {
  return { id: dto.id, fullName: dto.fullName, email: dto.email, role: dto.role as UserRole, status: dto.status as UserStatus, mustChangePassword: dto.mustChangePassword };
}

Port + DI token

domain/repositories/users.repository.tsdomain

The interface defines the contract the domain depends on. The InjectionToken makes it bindable at runtime — TypeScript interfaces are erased at compilation. The port returns DTO envelopes; the use case owns all validation and mapping.

export interface IUsersRepository {
  list(): Promise<UsersDtoRs>;
  create(rq: CreateUserDtoRq): Promise<UserItemDtoRs>;
  update(id: string, rq: UpdateUserDtoRq): Promise<UserItemDtoRs>;
  setStatus(id: string, rq: SetUserStatusDtoRq): Promise<UserItemDtoRs>;
}
export const USERS_REPOSITORY = new InjectionToken<IUsersRepository>('USERS_REPOSITORY');

Repository impl

data/repositories/users.repository.impl.tsdata

Fetch-only: calls HttpClientService and returns the typed envelope directly. No validation, no mapping — the repository simply delegates to HTTP. @Injectable({ providedIn: 'root' }) so Angular creates a single shared instance.

@Injectable({ providedIn: 'root' })
export class UsersRepositoryImpl implements IUsersRepository {
  private readonly http = inject(HttpClientService);
  list(): Promise<UsersDtoRs> { return this.http.get<UsersDtoRs>('/api/users'); }
  create(rq: CreateUserDtoRq): Promise<UserItemDtoRs> { return this.http.post<UserItemDtoRs>('/api/users', { body: rq }); }
  update(id: string, rq: UpdateUserDtoRq): Promise<UserItemDtoRs> { return this.http.patch<UserItemDtoRs>(`/api/users/${id}`, { body: rq }); }
  setStatus(id: string, rq: SetUserStatusDtoRq): Promise<UserItemDtoRs> { return this.http.patch<UserItemDtoRs>(`/api/users/${id}/status`, { body: rq }); }
}

Use case

domain/usecases/user-management/list-users.use-case.tsdomain

Extends UseCase<void, User[]>. execute() calls the repo via the injected port, validates every DTO with isUserDtoRsValid, and maps to domain User objects via toUser. Try/catch and Result wrapping are inherited from UseCase.run().

@Injectable({ providedIn: 'root' })
export class ListUsersUseCase extends UseCase<void, User[]> {
  private readonly repo = inject(USERS_REPOSITORY);
  constructor() { super('ListUsers'); }
  protected async execute(): Promise<User[]> {
    const res = await this.repo.list();
    if (!res.data.every(isUserDtoRsValid)) throw new AppError('Invalid user data received', 'validation');
    return res.data.map(toUser);
  }
}

ViewModel

presentation/pages/user-management/users.viewmodel.tspresentation

Route-scoped via providers: [UsersViewModel] in app.routes.ts — a fresh instance per navigation. Exposes signals the page binds to. On failure, shows an error toast via NotificationService (this.notify.error(r.error.message)) — no error signal, no stale-data clear. No try/catch — UseCase.run() always returns a Result.

@Injectable()
export class UsersViewModel {
  private readonly listUsers = inject(ListUsersUseCase);
  private readonly notify = inject(NotificationService);

  readonly users = signal<User[]>([]);
  readonly loading = signal(false);

  async load(): Promise<void> {
    this.loading.set(true);
    const r = await this.listUsers.run();
    this.loading.set(false);
    if (r.ok) this.users.set(r.data);
    else this.notify.error(r.error.message);
  }
}

Page

presentation/pages/user-management/user-management.page.tspresentation

A standalone component that injects UsersViewModel (provided by the route) and calls vm.load() on init. It reads signals reactively — no manual subscriptions. Errors and success confirmations surface via NotificationService.

export class UserManagementPage implements OnInit {
  protected readonly vm = inject(UsersViewModel);
  readonly ROLE_LABELS = ROLE_LABELS;

  ngOnInit(): void { void this.vm.load(); }
}

Global providers + route

app.config.ts · app.routes.ts

Repository token→impl bindings are global in app.config.ts; use cases and UsersRepositoryImpl are providedIn: 'root'. Only the UsersViewModel is route-scoped, giving each navigation a fresh instance.

// app.config.ts (excerpt)
providers: [

  ...AUTH_PROVIDERS,
  ...USERS_PROVIDERS,   // { provide: USERS_REPOSITORY, useClass: UsersRepositoryImpl }

  canActivate: [roleGuard('admin')],

  providers: [UsersViewModel],
}

Repository-port pattern

All HTTP-backed features follow the fetch-only / validate-in-use-case pattern: the port returns the transport DTO envelope (e.g. Promise<UsersDtoRs>); the use case is the single place that validates (isUserDtoRsValid) and maps to the domain model (toUser). The repository never validates or maps — it simply delegates to HttpClientService and returns whatever envelope the API returns. For local / trusted data (e.g. a KeyValueStore-backed feature), the port may return the domain model directly; no DTO or validation layer is needed in that case.

How to add a feature

  1. Create the folders features/<feature>/{data,domain,presentation/pages/<screen>,testing}.
  2. DTO + validator — response DTOs and their validator together in data/dto/<screen>/<resource>.dto.ts; each request DTO in its own file data/dto/<screen>/<operation>.dto.ts. Use shared/ when the DTO is used by the store, interceptor, app-init, or across multiple screens (HTTP-backed features).
  3. Model + mapper — screen-specific input types in domain/model/<screen>/<entity>.ts; feature-wide aggregate + mappers in domain/model/shared/<aggregate>.ts.
  4. Port + token: I…Repository interface + InjectionToken in domain/repositories/<entity>.repository.ts.
  5. Repository impl (providedIn: 'root') in data/repositories/<entity>.repository.impl.ts.
  6. Providers array …_PROVIDERS in data/<feature>.providers.ts; spread into app.config.ts. Other non-screen data files (interceptors, token stores) also stay at the data/ root.
  7. Use case (providedIn: 'root') extending UseCase in domain/usecases/<screen>/<verb>-<entity>.use-case.ts. The screen that triggers the operation owns it. Use cases owned by the store, interceptor, or app-init — or shared across multiple screens — go in domain/usecases/shared/.
  8. Screen folder at presentation/pages/<screen>/ containing <screen>.page.ts, <screen>.page.html, and (when the screen has state) <screen>.viewmodel.ts. Non-screen presentation files (stores, guards) stay at the presentation/ root.
  9. Barrel index.ts; wire the route with providers: [FeatureViewModel] (route-scoped).
  10. Tests in testing/ — place specs at the mirrored path (e.g. testing/presentation/pages/<screen>/<screen>.viewmodel.spec.ts, testing/domain/usecases/…). Specs import the unit under test via @features/@core aliases; Jest discovers them via its **/*.spec.ts glob — no config change needed.
