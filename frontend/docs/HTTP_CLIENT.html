HttpClientService — all-verb HTTP client

A typed Promise wrapper over Angular HttpClient. Five verbs, configurable retry/backoff on transport failures, and unified error mapping via toAppError.

Where it sits: src/app/core/network/api/http-client.ts. Repositories inject HttpClientService directly and return the DTO envelope; the use case validates and maps.

Interface

HttpRequestOptions

coresrc/app/core/network/api/http-client.ts

All five verb methods accept an optional HttpRequestOptions bag. Only the fields relevant to the call need to be present.

export type HttpMethod = 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';

export interface HttpRequestOptions {
  body?:    unknown;
  headers?: Record<string, string>;
  params?:  Record<string, string | number | boolean>;
}

Five verb methods

coresrc/app/core/network/api/http-client.ts

Each method returns Promise<T>. On success the promise resolves with the parsed JSON body. On failure it rejects with an AppError (see Error Handling).

@Injectable({ providedIn: 'root' })
export class HttpClientService {
  get<T>(path: string, opts?: HttpRequestOptions): Promise<T>;
  post<T>(path: string, opts?: HttpRequestOptions): Promise<T>;
  put<T>(path: string, opts?: HttpRequestOptions): Promise<T>;
  patch<T>(path: string, opts?: HttpRequestOptions): Promise<T>;
  delete<T>(path: string, opts?: HttpRequestOptions): Promise<T>;
}

The path is appended to env.api.baseUrl. Query string parameters go in opts.params (serialised via HttpParams); never embed them in the path string.

Retry & timeout

Transient-only retry with exponential backoff

core

Transport failures (status 0) and TimeoutError are retried. HTTP errors (4xx/5xx) are never retried — they represent server responses, not connectivity gaps.

// inside request() — adapted from http-client.ts
obs.pipe(
  timeout(env.api.timeoutMs),           // default 10 000 ms
  retry({
    count: env.api.maxRetries,            // 2 retries → 3 total attempts
    delay: (error, attempt) => {
      if (!this.isTransient(error)) throw error;  // non-transient → propagate immediately
      const ms = env.api.backoffMs[attempt - 1] ?? 0; // [500, 1500]
      return timer(ms);
    },
  }),
)

Error mapping — toAppError

toAppError

coresrc/app/core/network/api/http-error.ts

Every rejection passes through toAppError before reaching the caller. This converts Angular's HttpErrorResponse (or an rxjs TimeoutError) into a typed AppError. Callers always receive an AppError — never a raw Angular error.

export function toAppError(err: unknown): AppError {
  if (err instanceof HttpErrorResponse) {
    if (err.status === 0) return new AppError(err.message || 'Network request failed', 'network');
    const body = err.error as { message?: string; code?: string } | string | null;
    const message = body && typeof body === 'object' && body.message ? body.message : `HTTP ${err.status}`;
    const code    = body && typeof body === 'object' ? body.code : undefined;
    const kind    = err.status === 401 ? 'auth' : 'http';
    return new AppError(message, kind, err.status, code);
  }
  return new AppError('Network request failed', 'network'); // TimeoutError or other transport failure
}
ConditionAppError.kindNotes
status === 0'network'No response received (offline, DNS, CORS preflight)
status === 401'auth'Unauthenticated; interceptor attempts a token refresh first
Other non-2xx'http'Carries status and optional backend code string
