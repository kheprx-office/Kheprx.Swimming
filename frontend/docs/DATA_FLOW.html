Step-by-step trace

Six steps from page init down to the network and back. Each snippet is drawn from the real source files.

  1. Page init triggers vm.load() — presentation UserManagementPage injects UsersViewModel (provided by the route) and calls void this.vm.load() in ngOnInit(). The page never touches the use case or HTTP layer directly. 
    export class UserManagementPage implements OnInit {
  protected readonly vm = inject(UsersViewModel);
  readonly ROLE_LABELS = ROLE_LABELS;

  ngOnInit(): void { void this.vm.load(); }
}
  2. ViewModel sets loading state and awaits the use case — presentation UsersViewModel.load() flips loading to true, then suspends on listUsers.run(). No try/catch here — the base UseCase already normalizes all errors into a Result. 
    this.loading.set(true);
const r = await this.listUsers.run();
  3. UseCase.run() wraps execute() in a single try/catch — domain The base class owns error handling once for every subclass. Any thrown value is caught: an AppError is forwarded as-is; anything else becomes 'unknown'. 
    async run(input: I): Promise<Result<O>> {
  try {
    return ok(await this.execute(input));
  } catch (e) {
    const error =
      e instanceof AppError ? e : new AppError('Unexpected error', 'unknown');
    return fail(error);
  }
}
  4. ListUsersUseCase.execute() calls the repo, validates DTOs, maps to domain — domain The use case fetches via the injected port (USERS_REPOSITORY), validates every item with isUserDtoRsValid, and maps the raw DTOs to domain User objects via toUser. Validation failure throws an AppError of kind 'validation'. 
    const res = await this.repo.list();
if (!res.data.every(isUserDtoRsValid)) {
  throw new AppError('Invalid user data received', 'validation');
}
return res.data.map(toUser);
  5. UsersRepositoryImpl.list() delegates directly to HttpClientService — data The repository is fetch-only: it calls this.http.get<UsersDtoRs>('/api/users') and returns the typed envelope. No validation, no mapping. HttpClientService handles retries, timeouts, and error conversion to AppError internally. 
    list(): Promise<UsersDtoRs> { return this.http.get<UsersDtoRs>('/api/users'); }
  6. Result bubbles back — ViewModel sets signals, page reacts — presentation After listUsers.run() resolves, the ViewModel inspects r.ok. On success it populates users; on failure it calls this.notify.error(r.error.message) to show a toast via NotificationService — no error signal is set, and the users list is not cleared. The page reads these signals reactively — no manual subscription needed. 
    this.loading.set(false);
if (r.ok) this.users.set(r.data);
else this.notify.error(r.error.message);

Where errors come from

Each layer throws a typed AppError; UseCase.run() catches once and normalizes any non-AppError to 'unknown', returning a Result.

OriginAppError kind
http-client: transport failure / timeoutnetwork
http-client: non-2xx responsehttp (+ status)
use case: failed DTO validationvalidation
KeyValueStore: storage failure / corrupt objectstorage
CryptoService: encrypt/decrypt failurecrypto
any other throwunknown (normalized by UseCase.run)
