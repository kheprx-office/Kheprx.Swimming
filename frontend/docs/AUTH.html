DTOs + validators — data/dto/{login,change-password,shared}/

Response DTOs, request bodies, and validators

datasrc/app/features/auth/data/dto/{login,change-password,shared}/

Raw transport shapes returned by the Identity backend. The DTO monolith is split by operation and screen: each request DTO gets its own file under the screen subfolder that owns the operation (login/login.dto.ts, change-password/change-password.dto.ts). Response DTOs and their validators live together in shared/ because they are consumed by the store, interceptor, and multiple use cases. Response DTOs extend BaseResponseRs<T> (the API envelope). Validators check each field before the use case maps to a domain model; role is hardened against ROLE_LABELS so an unrecognised role is treated as invalid data.

import { BaseResponseRs } from '@core/network/api/base-response-rs';
import { ROLE_LABELS } from '@core/domain/roles';

// Response shapes (raw / untrusted transport)
export interface SessionDtoRs {
  accessToken: string; refreshToken: string;
  role: string; userId: string; mustChangePassword: boolean;
}
export interface CurrentUserDtoRs {
  userId: string; email: string; fullName: string; role: string;
}

// API envelopes
export interface SessionItemDtoRs     extends BaseResponseRs<SessionDtoRs>     {}
export interface CurrentUserItemDtoRs extends BaseResponseRs<CurrentUserDtoRs> {}

// Request bodies
export interface LoginDtoRq          { email: string; password: string; }
export interface RefreshDtoRq        { refreshToken: string; }
export interface ChangePasswordDtoRq { currentPassword: string; newPassword: string; }

// Validators (called by use cases before mapping)
export function isSessionDtoRsValid(dto: SessionDtoRs): boolean {
  return (
    typeof dto.accessToken  === 'string' && dto.accessToken.length  > 0 &&
    typeof dto.refreshToken === 'string' && dto.refreshToken.length > 0 &&
    typeof dto.userId       === 'string' && dto.userId.length       > 0 &&
    typeof dto.role         === 'string' &&
    Object.prototype.hasOwnProperty.call(ROLE_LABELS, dto.role) &&
    typeof dto.mustChangePassword === 'boolean'
  );
}

export function isCurrentUserDtoRsValid(dto: CurrentUserDtoRs): boolean {
  return (
    typeof dto.userId   === 'string' && dto.userId.length > 0 &&
    typeof dto.email    === 'string' &&
    typeof dto.fullName === 'string' &&
    typeof dto.role     === 'string' &&
    Object.prototype.hasOwnProperty.call(ROLE_LABELS, dto.role)
  );
}

Domain models + mappers — domain/model/{login,change-password,shared}/

AuthSession · AuthTokens · AuthPrincipal

domainsrc/app/features/auth/domain/model/shared/auth.ts

The auth model is split by screen. Screen-specific input types live under their screen subfolder: LoginInput in domain/model/login/login.ts; ChangePasswordInput in domain/model/change-password/change-password.ts. Feature-wide types and mappers live in domain/model/shared/auth.ts. mustChangePassword is a session-lifecycle flag (forced first-login change) surfaced by login, refresh, and change-password; it is not part of the identity principal. Mappers convert DTO shapes to domain models — the only place where casting happens.

// domain/model/login/login.ts
export interface LoginInput          { email: string; password: string; }

// domain/model/change-password/change-password.ts
export interface ChangePasswordInput { currentPassword: string; newPassword: string; }

// domain/model/shared/auth.ts
export interface AuthTokens   { accessToken: string; refreshToken: string; }
export interface AuthPrincipal { role: UserRole; userId: string; }
export interface AuthSession   { tokens: AuthTokens; principal: AuthPrincipal; mustChangePassword: boolean; }

// Mappers — called by use cases after validation
export function toAuthSession(dto: SessionDtoRs): AuthSession {
  return {
    tokens: { accessToken: dto.accessToken, refreshToken: dto.refreshToken },
    principal: { role: dto.role as UserRole, userId: dto.userId },
    mustChangePassword: dto.mustChangePassword,
  };
}

export function toAuthTokens(dto: SessionDtoRs): AuthTokens {
  return { accessToken: dto.accessToken, refreshToken: dto.refreshToken };
}

export function toAuthPrincipal(dto: CurrentUserDtoRs): AuthPrincipal {
  return { role: dto.role as UserRole, userId: dto.userId };
}

Repository — port, impl & providers

IAuthRepository + AUTH_REPOSITORY

domainsrc/app/features/auth/domain/repositories/auth.repository.ts

The domain contract. Methods accept request DTOs and return the raw API envelopes (SessionItemDtoRs / CurrentUserItemDtoRs). Validation and domain mapping are the use cases' responsibility, not the repository's.

export interface IAuthRepository {
  login(rq: LoginDtoRq):                           Promise<SessionItemDtoRs>;
  refresh(rq: RefreshDtoRq):                        Promise<SessionItemDtoRs>;
  logout():                                            Promise<void>;
  me():                                                Promise<CurrentUserItemDtoRs>;
  changePassword(rq: ChangePasswordDtoRq):           Promise<SessionItemDtoRs>;
}
export const AUTH_REPOSITORY = new InjectionToken<IAuthRepository>('AUTH_REPOSITORY');

AuthRepositoryImpl — fetch-only

datasrc/app/features/auth/data/repositories/auth.repository.impl.ts

Delegates every method to HttpClientService and returns the envelope unchanged. The Bearer token is attached by authInterceptor — the impl itself is auth-unaware.

@Injectable({ providedIn: 'root' })
export class AuthRepositoryImpl implements IAuthRepository {
  private readonly http = inject(HttpClientService);

  login(rq: LoginDtoRq):                 Promise<SessionItemDtoRs>     { return this.http.post('/api/auth/login',           { body: rq }); }
  refresh(rq: RefreshDtoRq):              Promise<SessionItemDtoRs>     { return this.http.post('/api/auth/refresh',         { body: rq }); }
  async logout():                          Promise<void>               { await  this.http.post('/api/auth/logout',          {}); }
  me():                                    Promise<CurrentUserItemDtoRs> { return this.http.get ('/api/auth/me');              }
  changePassword(rq: ChangePasswordDtoRq): Promise<SessionItemDtoRs>    { return this.http.post('/api/auth/change-password', { body: rq }); }
}

AUTH_PROVIDERS — composition root binding

datasrc/app/features/auth/data/auth.providers.ts

Binds the AUTH_REPOSITORY token to AuthRepositoryImpl. Spread into appConfig.providers alongside USERS_PROVIDERS and provideHttpClient(withInterceptors([authInterceptor])).

export const AUTH_PROVIDERS: Provider[] = [
  { provide: AUTH_REPOSITORY, useClass: AuthRepositoryImpl },

Use cases

LoginUseCase

domainsrc/app/features/auth/domain/usecases/login/login.use-case.ts

Calls repo.login(), validates the session DTO, maps to AuthSession, and persists both tokens in TokenStore. Returns the full session including mustChangePassword.

protected async execute({ email, password }: LoginInput): Promise<AuthSession> {
  const res = await this.repo.login({ email, password });
  if (!isSessionDtoRsValid(res.data)) throw new AppError('Invalid session data received', 'validation');
  const session = toAuthSession(res.data);
  await this.tokens.save(session.tokens);
  return session;
}

RefreshTokenUseCase

domainsrc/app/features/auth/domain/usecases/shared/refresh-token.use-case.ts

Reads the stored refresh token, calls repo.refresh(), validates the returned session DTO (the backend re-issues a full SessionDtoRs on refresh), extracts the new token pair via toAuthTokens(), and saves both. Throws AppError('auth', 401) if no refresh token is stored.

protected async execute(): Promise<AuthTokens> {
  const refresh = await this.store.getRefresh();
  if (!refresh) throw new AppError('No refresh token', 'auth', 401);
  const res = await this.repo.refresh({ refreshToken: refresh });
  if (!isSessionDtoRsValid(res.data)) throw new AppError('Invalid session data received', 'validation');
  const tokens = toAuthTokens(res.data);
  await this.store.save(tokens);
  return tokens;
}

LogoutUseCase

domainsrc/app/features/auth/domain/usecases/account/logout.use-case.ts

Best-effort server-side session revoke via repo.logout() (a failed revoke is swallowed), then clears both tokens from TokenStore. The local clear always succeeds regardless of backend reachability.

protected async execute(): Promise<void> {
  try { await this.repo.logout(); } catch { /* best-effort */ }
  await this.store.clear();
}

ChangePasswordUseCase

domainsrc/app/features/auth/domain/usecases/change-password/change-password.use-case.ts

Calls repo.changePassword(), validates and maps the response (the backend rotates tokens on change), and saves the new token pair. Returns the updated AuthSession — the session store applies it immediately.

protected async execute({ currentPassword, newPassword }: ChangePasswordInput): Promise<AuthSession> {
  const res = await this.repo.changePassword({ currentPassword, newPassword });
  if (!isSessionDtoRsValid(res.data)) throw new AppError('Invalid session data received', 'validation');
  const session = toAuthSession(res.data);
  await this.tokens.save(session.tokens);
  return session;
}

LoadCurrentUserUseCase

domainsrc/app/features/auth/domain/usecases/shared/load-current-user.use-case.ts

Calls GET /api/auth/me via repo.me(), validates with isCurrentUserDtoRsValid(), and maps to AuthPrincipal via toAuthPrincipal(). Used by AuthSessionStore.rehydrate() on construction to validate a stored token against the real backend before restoring the session.

protected async execute(): Promise<AuthPrincipal> {
  const res = await this.repo.me();
  if (!isCurrentUserDtoRsValid(res.data)) throw new AppError('Invalid user data received', 'validation');
  return toAuthPrincipal(res.data);
}

Token storage — TokenStore

TokenStore

datasrc/app/features/auth/data/token-store.ts

Persists access and refresh tokens in localStorage via KeyValueStore. The interceptor reads the access token; RefreshTokenUseCase reads and updates both. AuthSessionStore.rehydrate() reads both to detect whether a prior session exists.

@Injectable({ providedIn: 'root' })
export class TokenStore {
  async save(t: AuthTokens): Promise<void> { /* saves both tokens */ }
  getAccess():  Promise<string | null> { /* reads access token */ }
  getRefresh(): Promise<string | null> { /* reads refresh token */ }
  async clear():  Promise<void>   { /* removes both keys */ }
}

AuthSessionStore — session signals

AuthSessionStore

presentationsrc/app/features/auth/presentation/auth-session.store.ts

The single source of truth for the current auth session, exposed as readonly signals. Pages and guards read from here; signIn/signOut/changePassword drive state changes. On construction, rehydrate() checks TokenStore for stored tokens and, if both are present, calls LoadCurrentUserUseCase.run() (GET /api/auth/me) to validate the token server-side before restoring the session. An expired or invalid token causes a normal re-login via the interceptor's 401 path.

@Injectable({ providedIn: 'root' })
export class AuthSessionStore {
  readonly session            = this._session.asReadonly();
  readonly isAuthenticated    = computed(() => this._session() !== null);
  readonly principal          = computed(() => this._session()?.principal ?? null);
  readonly role               = computed<UserRole | null>(() => this._session()?.principal.role ?? null);
  readonly mustChangePassword = computed<boolean>(() => this._session()?.mustChangePassword ?? false);

  constructor() { void this.rehydrate(); }

  async signIn(email: string, password: string): Promise<Result<AuthSession>> {
    const r = await this.loginUseCase.run({ email, password });
    if (r.ok) this._session.set(r.data);
    return r;
  }

  async signOut(): Promise<void> {
    await this.logoutUseCase.run();
    this._session.set(null);
  }

  async changePassword(currentPassword: string, newPassword: string): Promise<Result<AuthSession>> {
    const r = await this.changePasswordUseCase.run({ currentPassword, newPassword });
    if (r.ok) this._session.set(r.data);
    return r;
  }

  private async rehydrate(): Promise<void> {
    const accessToken  = await this.tokens.getAccess();
    const refreshToken = await this.tokens.getRefresh();
    if (!accessToken || !refreshToken) return;
    const r = await this.loadCurrentUser.run();
    if (r.ok) this._session.set({ tokens: { accessToken, refreshToken }, principal: r.data, mustChangePassword: false });
  }
}

authInterceptor — Bearer + 401 retry

authInterceptor

datasrc/app/features/auth/data/auth.interceptor.ts

Registered via provideHttpClient(withInterceptors([authInterceptor])). Reads the access token from TokenStore, attaches a Bearer header to every outgoing request, and on a 401 response makes one refresh attempt via RefreshTokenUseCase.run() before retrying the original request. If the refresh also fails, tokens are cleared and the router navigates to /login.

The 401→refresh→retry path is bypassed for /api/auth/refresh, /api/auth/login, and /api/auth/logout: a 401 on the refresh endpoint itself must not trigger another refresh (infinite loop); login and logout 401s have no live session to refresh.

const AUTH_NO_REFRESH = ['/api/auth/refresh', '/api/auth/login', '/api/auth/logout'];
const bypassesRefresh = (url: string) => AUTH_NO_REFRESH.some((path) => url.includes(path));

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  return from(tokens.getAccess()).pipe(
    switchMap((access) =>
      next(withAuth(req, access)).pipe(
        catchError((err) => {
          if (err?.status !== 401 || bypassesRefresh(req.url)) return throwError(() => err);
          // one refresh attempt, then retry original request
          return from(refresh.run()).pipe(
            switchMap((result) => {
              if (!result.ok) { void tokens.clear(); void router.navigate(['/login']); return throwError(() => err); }
              return next(withAuth(req, result.data.accessToken));
            }),
          );
        }),
      ),
    ),
  );
};

Guards

authGuard & roleGuard

presentationsrc/app/features/auth/presentation/auth.guard.ts

authGuard blocks anonymous access; roleGuard additionally checks the role. Both read signals from AuthSessionStore — no async work needed. Both redirect unauthenticated users to /login; authenticated users lacking the required role are redirected to /.

// authGuard: redirect unauthenticated users to /login
export const authGuard: CanActivateFn = () => {
  const auth   = inject(AuthSessionStore);
  const router = inject(Router);
  if (!auth.isAuthenticated()) { router.navigate(['/login']); return false; }
  return true;
};

// roleGuard: requires one of `roles`; others are sent to '/'
export const roleGuard = (...roles: UserRole[]): CanActivateFn => () => {
  const auth   = inject(AuthSessionStore);
  const router = inject(Router);
  if (!auth.isAuthenticated()) { router.navigate(['/login']); return false; }
  const role = auth.role();
  if (!role || !roles.includes(role)) { router.navigate(['/']); return false; }
  return true;
};

Usage in route config (see Composition Root for the full route table):

{ path: '', component: LayoutComponent, canActivate: [authGuard], children: [
  { path: 'user-management', canActivate: [roleGuard('admin')], loadComponent: () => /* ... */ },
] }
