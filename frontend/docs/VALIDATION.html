Base Frontend — Validation & Forms

Two validation sites: type-guard DTO validation at the use-case boundary for untrusted remote data, and signal-backed inline guards in the ViewModel for trusted user input.

Layers: data presentation

Boundary (DTO) validation — untrusted remote data

isUserDtoRsValid

datasrc/app/features/user-management/data/dto/user-management/user.dto.ts

HTTP responses are untrusted: the server could return an unexpected shape, a field could be null, or an enumerated value could drift. The DTO type guard isUserDtoRsValid asserts the exact runtime shape before the data is allowed past the boundary into a domain model.

import { ROLE_LABELS } from '@core/domain/roles';

export function isUserDtoRsValid(dto: UserDtoRs): boolean {
  return (
    typeof dto.id === 'string' && dto.id.length > 0 &&
    typeof dto.fullName === 'string' &&
    typeof dto.email === 'string' &&
    typeof dto.role === 'string' &&
    Object.prototype.hasOwnProperty.call(ROLE_LABELS, dto.role) && // role-hardening: only known roles pass
    (dto.status === 'active' || dto.status === 'disabled') &&          // status ∈ {active, disabled}
    typeof dto.mustChangePassword === 'boolean'
  );
}

Two checks deserve attention. The role is validated against ROLE_LABELS — the shared-kernel map of all known roles (admin | manager | moqawel | worker) — using Object.prototype.hasOwnProperty.call rather than enumerating string literals; this means adding a new role to ROLE_LABELS automatically admits it at the boundary with no guard change. The status field is constrained to the closed union 'active' | 'disabled' by an explicit equality check — any other string (e.g. 'pending') would be rejected.

The guard runs at the use-case boundary — one architectural layer above the repository port that fetches the raw response. If any item in the response array fails the check, a validation AppError is thrown, which UseCase.run() catches and wraps into a Result.

// ListUsersUseCase.execute() — features/user-management/domain/usecases/user-management/list-users.use-case.ts
protected async execute(): Promise<User[]> {
  const res = await this.repo.list();
  if (!res.data.every(isUserDtoRsValid)) {
    throw new AppError('Invalid user data received', 'validation');
  }
  return res.data.map(toUser);
}

Only data that passes the guard is mapped to a User domain model via toUser. This keeps the domain layer free of transport-layer assumptions — the guard is the explicit contract between the remote/untrusted repository port and the rest of the application.

Signal-backed form validation — trusted user input

UsersViewModel — save

presentationsrc/app/features/user-management/presentation/pages/user-management/users.viewmodel.ts

User input in the app's forms (login, user-management modal) is handled through signal-backed fields declared on the ViewModel — not Angular reactive forms. Each field is a plain signal(); validation is enforced via inline guards in the action method, executed before any use case is called.

// signal-backed form fields — declared on UsersViewModel
readonly formFullName = signal('');
readonly formEmail    = signal('');
readonly formRole     = signal<UserRole>('manager');
readonly formPassword = signal('');
readonly formStatus   = signal<UserStatus>('active');

// inline guard in the action method — before calling any use case
async save(): Promise<void> {
  if (!this.formFullName().trim()) { this.notify.error('الاسم مطلوب'); return; }
  // ... proceed to createUser or updateUser use case
}

This approach avoids the FormGroup/FormBuilder ceremony and keeps validation logic co-located with the action. The template binds to signals directly (e.g. (input)="formFullName.set($event.target.value)"), and the ViewModel surfaces error feedback via NotificationService — not a reactive validator or error state signal.

Exception: change-password.page.ts uses FormsModule/ngModel for two-way binding on its password fields. It is the one place in the codebase that opts into Angular's built-in form binding; no other page uses FormGroup, Validators, or ReactiveFormsModule.

Where to validate what

Source of data Where it is validated Mechanism
Remote API (untrusted) use-case boundary is…DtoRsValid guard → AppError('…', 'validation')
User input (forms) the ViewModel action method signal fields + inline guard before the use-case call; error surfaced via NotificationService (exception: change-password.page.ts uses FormsModule/ngModel)
Local store (trusted, app-written) not re-validated round-tripped via KeyValueStore
