ApiResponse<T> — the typed HTTP envelope

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Responses/ApiResponse.cs

The generic HTTP response wrapper returned by all API endpoints. Extends BaseApiResponse and adds a typed Data payload.

namespace Kheprx.BaseBackend.SharedKernel.Responses;

public sealed class ApiResponse<T> : BaseApiResponse
{
    public T? Data { get; init; }

    public static ApiResponse<T> Success(string message, T? data) =>
        new() { SuccessStatus = true, Message = message, Data = data };

    public static ApiResponse<T> Failure(string message, string error) =>
        new() { SuccessStatus = false, Message = message, Error = error };
}

What's happening here: two static factory methods — Success and Failure — are the canonical way to construct an ApiResponse<T>. Success sets SuccessStatus = true and carries a typed Data value; Failure sets SuccessStatus = false and carries an Error string. All properties use init setters, making instances immutable after construction. Controllers use these factories to produce a uniform JSON shape across every endpoint.

BaseApiResponse — the common envelope fields

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Responses/BaseApiResponse.cs

The abstract base that defines the three fields present on every API response: success flag, human-readable message, and optional error detail.

namespace Kheprx.BaseBackend.SharedKernel.Responses;

public abstract class BaseApiResponse
{
    public bool SuccessStatus { get; init; }
    public string Message { get; init; } = string.Empty;
    public string? Error { get; init; }
}

What's happening here: BaseApiResponse is abstract so it can never be instantiated directly — only through its concrete subclass ApiResponse<T>. It declares SuccessStatus (whether the operation succeeded), Message (a human-readable summary, defaulting to string.Empty), and Error (nullable detail string for failures). All three are init-only, enforcing immutability. Splitting the envelope into base + generic subclass lets controllers return ApiResponse<T> without losing the common fields when the type parameter is not known.

AppLanguage — the app-language switch

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Resources/AppLanguage.cs

The single point that determines the response language for all resource classes. Current returns "ar" today; later this will be resolved per request from the Accept-Language header without touching any message class.

namespace Kheprx.BaseBackend.SharedKernel.Resources;

public static class AppLanguage
{
    public static string Current => "ar";
}

What's happening here: every …Messages method accepts a string lang parameter and switches on it. Controllers and validators call those methods as ProductMessages.Errors.ProductNotFound(AppLanguage.Current) — passing AppLanguage.Current each time. Changing "ar" to another value here would flip the entire app's response language in one edit. The BaseApiController already exposes an AcceptLanguage helper for the future per-request step.

CommonMessages — shared localized texts

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Resources/CommonMessages.cs

Localized message strings shared across modules: ValidationFailed, ValidationFallback, ServerError, and generic field-validation texts (email, password, full name). Feature-specific messages live in the module's own Application Resources/ class.

public static class CommonMessages
{
    public static class Errors
    {
        public static string ValidationFailed(string lang) => lang switch
        {
            "ar" => "فشل التحقق من البيانات",
            _ => "Validation failed"
        };

        public static string ValidationFallback(string lang) => lang switch
        {
            "ar" => "حدث خطأ في التحقق من البيانات",
            _ => "One or more validation errors occurred."
        };

        public static string EmailRequired(string lang) => lang switch
        {
            "ar" => "البريد الإلكتروني مطلوب",
            _ => "Email is required"
        };
        // … ServerError, EmailInvalid, EmailTooLong, PasswordRequired, PasswordMinLength, PasswordTooLong, FullNameRequired, FullNameTooLong
    }
}

What's happening here: ValidationFailed and ValidationFallback are called by ValidationFilter and ModelStateResponse; the field texts are used by validators (e.g. LoginRequestValidator). Modules keep feature-specific texts in their own Application Resources/ classes (e.g. ProductMessages, AuthMessages).

BaseEntity — the aggregate base

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Domain/BaseEntity.cs

Abstract base class that every domain entity inherits from. Provides the surrogate key and audit timestamps, plus a Touch() helper to stamp UpdatedAt.

namespace Kheprx.BaseBackend.SharedKernel.Domain;

public abstract class BaseEntity
{
    public int Id { get; protected set; }
    public DateTime CreatedAt { get; protected set; } = DateTime.UtcNow;
    public DateTime? UpdatedAt { get; protected set; }

    protected void Touch() => UpdatedAt = DateTime.UtcNow;
}

What's happening here: Id is an int surrogate key with a protected setter so EF Core can populate it but application code cannot assign it directly. CreatedAt defaults to DateTime.UtcNow at construction time and is also protected set. UpdatedAt is nullable — it starts as null and is stamped the first time the entity changes. Touch() is protected, so only the entity's own mutation methods (like Product.Rename) can call it — external code cannot bypass the domain's invariants to update the timestamp. See Domain for how Product extends this base.

DomainException — the domain error base

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Domain/DomainException.cs

Abstract base exception for all domain rule violations. The host's ExceptionHandlingMiddleware catches any DomainException and converts it to a clean HTTP 400 response.

namespace Kheprx.BaseBackend.SharedKernel.Domain;

public abstract class DomainException : Exception
{
    protected DomainException(string message) : base(message) { }
}

What's happening here: DomainException is abstract, so modules must subclass it (e.g. InvalidProductException : DomainException) rather than throwing it directly. The constructor is protected, as an additional signal that only subclasses can be instantiated. By inheriting from Exception, any DomainException is a standard .NET exception that propagates normally — but the host's middleware intercepts it before it becomes a 500. This keeps domain entities completely unaware of HTTP: they throw a domain exception, and the infrastructure layer translates it to an error response.

IModule — the module registration contract

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Modules/IModule.cs

The interface every module's registration class must implement. Defines the single method the host calls to let each module wire up its own services.

using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace Kheprx.BaseBackend.SharedKernel.Modules;

public interface IModule
{
    IServiceCollection Register(IServiceCollection services, IConfiguration configuration);
}

What's happening here: IModule is the registration contract between the host and each feature module. A module implements this interface in its own assembly (for example, CatalogModule : IModule) and uses Register to add its own services, validators, MediatR handlers, and EF Core context to the DI container. The host never needs to reference any module assembly directly — ModuleRegistration discovers implementations at runtime. See The IModule convention for a full walkthrough.

ModuleRegistration — the auto-discovery helper

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/Modules/ModuleRegistration.cs

Static helper with the AddModules extension method. Scans the output directory for Kheprx.BaseBackend.*.dll assemblies, loads any not yet in the process, then instantiates and invokes every concrete IModule implementation it finds.

using System.Reflection;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace Kheprx.BaseBackend.SharedKernel.Modules;

public static class ModuleRegistration
{
    public static IServiceCollection AddModules(this IServiceCollection services, IConfiguration configuration)
    {
        foreach (var module in DiscoverModules())
            module.Register(services, configuration);
        return services;
    }

    private static IEnumerable<IModule> DiscoverModules()
    {
        var loaded = new HashSet<string>(
            AppDomain.CurrentDomain.GetAssemblies().Select(a => a.GetName().Name!));

        foreach (var dll in Directory.GetFiles(AppContext.BaseDirectory, "Kheprx.BaseBackend.*.dll"))
        {
            var name = Path.GetFileNameWithoutExtension(dll);
            if (loaded.Add(name))
            {
                try { Assembly.LoadFrom(dll); }
                catch { /* skip assemblies that cannot be loaded */ }
            }
        }

        var moduleType = typeof(IModule);
        return AppDomain.CurrentDomain.GetAssemblies()
            .SelectMany(SafeGetTypes)
            .Where(t => moduleType.IsAssignableFrom(t) && t is { IsClass: true, IsAbstract: false })
            .Select(t => (IModule)Activator.CreateInstance(t)!);
    }

    private static IEnumerable<Type> SafeGetTypes(Assembly assembly)
    {
        try { return assembly.GetTypes(); }
        catch (ReflectionTypeLoadException ex) { return ex.Types.Where(t => t is not null)!; }
    }
}

What's happening here: AddModules is an IServiceCollection extension called once in the host's Program.cs. DiscoverModules first records which assemblies are already loaded (to avoid re-loading), then calls Directory.GetFiles to find every Kheprx.BaseBackend.*.dll in the application's output folder and loads any that are new. It then walks all loaded assemblies via SafeGetTypes (which swallows ReflectionTypeLoadException for partial-load scenarios), filters to concrete non-abstract types assignable to IModule, and activates each with Activator.CreateInstance. The result: the host registers all module services without a compile-time reference to any module assembly. See The IModule convention for the full picture.

In simple words: SharedKernel is the foundation everything else stands on. BaseApiResponse/ApiResponse<T> give every endpoint the same JSON envelope. BaseEntity gives every aggregate root its Id, timestamps, and Touch() — see Domain for usage. DomainException lets domain entities signal rule violations without knowing anything about HTTP. AppLanguage + CommonMessages provide the language switch and shared localized texts (validation, field errors) used by every module. IModule and ModuleRegistration wire every module into the host automatically — see The IModule convention for a full walkthrough. No module adds code here; they only consume it.
