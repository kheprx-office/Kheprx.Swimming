Layer code

Real implementation at each stop in the request chain.

Host / Api

ProductsController.GetAll

Kheprx.BaseBackend.Api/Controllers/ProductsController.cs

Receives the HTTP request. Extends BaseApiController which applies [ApiController] and [Route("api/[controller]")]. Returns ApiResponse<T> from SharedKernel as the envelope.

[HttpGet]
public async Task<ActionResult<ApiResponse<IReadOnlyList<ProductDto>>>> GetAll(CancellationToken ct)
    => Ok(ApiResponse<IReadOnlyList<ProductDto>>.Success(
        "Products retrieved", await _service.GetAllAsync(ct)));
Application

ProductService.GetAllAsync

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Application/Services/ProductService.cs

Implements IProductService — the use-case orchestration lives entirely in Application. Delegates data access to the repository through the IProductRepository port and uses the Mapperly source-generated CatalogMapper to convert Product entities to ProductDto records. It has no EF Core or database dependency.

public async Task<IReadOnlyList<ProductDto>> GetAllAsync(CancellationToken ct = default)
    => _mapper.ToDtoList(await _repository.GetAllAsync(ct));
Infrastructure

ProductRepository.GetAllAsync

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Infrastructure/Repositories/ProductRepository.cs

Implements IProductRepository — the repository port declared in Domain. Uses EF Core with AsNoTracking() (read-only, no change tracking) and OrderBy(p => p.Id) for stable ordering.

public async Task<IReadOnlyList<Product>> GetAllAsync(CancellationToken ct = default)
    => await _db.Products.AsNoTracking().OrderBy(p => p.Id).ToListAsync(ct);
Infrastructure

CatalogDbContext

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Infrastructure/Data/CatalogDbContext.cs

Module-scoped EF Core DbContext. Loads entity configurations from the assembly (Fluent API via ApplyConfigurationsFromAssembly). Each module has its own isolated DbContext — there is no shared cross-module context.

public sealed class CatalogDbContext : DbContext
{
    public CatalogDbContext(DbContextOptions<CatalogDbContext> options) : base(options) { }

    public DbSet<Product> Products => Set<Product>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(CatalogDbContext).Assembly);
        base.OnModelCreating(modelBuilder);
    }
}

Conventions

Rules that every endpoint in this codebase follows.

ConventionMechanismWhere defined
Response envelope All endpoints return ApiResponse<T> with .Success(message, data) or .Failure(message, errorCode). Never return raw data or bare error strings. src/SharedKernel/…/Responses/ApiResponse.cs
Validation ValidationFilter is registered globally. It resolves the matching IValidator<T> for each action argument and returns a 400 with ApiResponse<object>.Failure(…) on failure — before the action method runs. Kheprx.BaseBackend.Api/Filters/ValidationFilter.cs · validators in .Application/Validators/ · see Validation & Validation Guide
Error handling ExceptionHandlingMiddleware catches unhandled DomainException and converts it to a structured 400 JSON response using ApiResponse<object>.Failure(…). All other exceptions become 500. Kheprx.BaseBackend.Api/Middlewares/ExceptionHandlingMiddleware.cs
Routing All controllers extend BaseApiController which carries [ApiController] and [Route("api/[controller]")]. Routes are therefore api/products, api/orders, etc. — derived from the controller name automatically. Kheprx.BaseBackend.Api/Controllers/BaseApiController.cs
Cancellation Every action and service method accepts a CancellationToken ct parameter. ASP.NET Core injects the request's token automatically; it is threaded through to EF Core queries so the database call is cancelled when the client disconnects. Convention — enforced by code review and architecture tests.
CORS The template ships a permissive AllowAll policy (any origin, header, and method) as a local-development default. Tighten this before deploying to production by restricting allowed origins in ServiceCollectionExtensions.cs. Kheprx.BaseBackend.Api/Extensions/ServiceCollectionExtensions.cs

Add a new endpoint

Follow these steps to add e.g. GET /api/products/{id} or any other new action.

  1. Add a DTO and validator in Application Create a new request record (or reuse an existing one) in .Application/DTOs/ProductDtos.cs and a matching AbstractValidator<T> in .Application/Validators/ProductRequestValidators.cs. ValidationFilter will pick it up automatically.
  2. Extend IProductService and implement in ProductService Add the method signature to IProductService.cs and implement it in ProductService.cs — both in the Application layer — delegating to the repository and using CatalogMapper for entity-to-DTO conversion.
  3. Add a repository method if needed If the new endpoint requires a query not already on IProductRepository, add it to the port in Domain (.Domain/Repositories/IProductRepository.cs) and implement it in ProductRepository (Infrastructure) using EF Core. Use AsNoTracking() for read-only queries.
  4. Add the controller action In ProductsController, add the new [Http*] action method. It must: accept a CancellationToken ct, call the service, and return ActionResult<ApiResponse<T>> wrapping ApiResponse<T>.Success(…) or .Failure(…).
  5. Run dotnet test Add a unit test for the new service method in tests/Kheprx.BaseBackend.Catalog.UnitTests/ProductServiceTests.cs, then run dotnet test Kheprx.BaseBackend.sln to confirm all tests pass including the architecture tests.
