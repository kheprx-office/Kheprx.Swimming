The four projects

Each project has a single responsibility and strict inbound dependency rules.

Domain

Kheprx.BaseBackend.Catalog.Domain

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Domain/

The innermost layer. Contains the pure business model: aggregate roots (e.g. Product extending BaseEntity), value objects, and domain exceptions (e.g. InvalidProductException extending DomainException). No NuGet packages beyond SharedKernel. Business invariants — rules that must always hold regardless of how the domain object was created — live here as validation inside entity constructors or methods.

May depend on: SharedKernel only.

Read more — Domain in detail →

Application

Kheprx.BaseBackend.Catalog.Application

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Application/

Defines the use-case contracts and their implementations: IProductService with its ProductService implementation (the orchestration), ProductDtos.cs (request/response records), CatalogMapper (Mapperly source-generated mapper annotated with [Mapper]), and ProductRequestValidators (FluentValidation rules). Consumes the repository port declared in Domain. No EF Core or database references allowed.

May depend on: Domain, SharedKernel.

Read more — Application in detail →

Infrastructure

Kheprx.BaseBackend.Catalog.Infrastructure

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Infrastructure/

Implements the data-access ports and wires up the module. Key files: CatalogDbContext (module-scoped EF Core context), ProductRepository (implements IProductRepository from Domain), CatalogModuleApi (implements ICatalogModule from Contracts), and CatalogModule (implements IModule — the DI registration entry point). The Migrations/ subfolder is auto-generated by the EF Core tooling.

May depend on: Domain, Application, Contracts, SharedKernel.

Read more — Infrastructure in detail →

Contracts

Kheprx.BaseBackend.Catalog.Contracts

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Contracts/

A deliberately thin project containing only the interface(s) that other modules or the host may reference — for example ICatalogModule. This is the only project in the module that external assemblies may take a project reference to. Keeping it thin enforces the module boundary: other modules cannot accidentally depend on domain entities, EF contexts, or service implementations.

May depend on: SharedKernel only (no Domain or Application types leak out).

SharedKernel building blocks

Cross-cutting types in src/SharedKernel/Kheprx.BaseBackend.SharedKernel/ — used by every module, never module-specific.

SharedKernel

Kheprx.BaseBackend.SharedKernel

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/

ApiResponse<T> — the HTTP response envelope. Every endpoint returns this type. Has two static factories: .Success(message, data) and .Failure(message, errorCode). Defined in Responses/ApiResponse.cs.

BaseEntity — abstract base class for aggregate roots. Provides an int Id, CreatedAt, and UpdatedAt so entities don't repeat these common properties. Defined in Domain/BaseEntity.cs.

DomainException — base class for all domain-level errors. ExceptionHandlingMiddleware catches this type and converts it to a 400 Bad Request response. Defined in Domain/DomainException.cs.

IModule — the registration contract every module entry point must implement. Declares a single method: IServiceCollection Register(IServiceCollection, IConfiguration). Defined in Modules/IModule.cs.

AddModules() — the IServiceCollection extension method called in Program.cs. Uses ModuleRegistration.Discover to scan all loaded Kheprx.BaseBackend.*.dll assemblies for IModule implementations and calls Register on each. Defined in Modules/ModuleRegistration.cs.

The IModule convention

Every module exposes exactly one IModule implementation in its Infrastructure project. The host auto-discovers any class implementing IModule in any Kheprx.BaseBackend.*.dll assembly loaded at startup via ModuleRegistration.Discover called by AddModules().

Infrastructure

CatalogModule — real Register body

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Infrastructure/CatalogModule.cs

Registers the module's EF Core context, the Mapperly mapper singleton, the repository, the service, and the public Contracts implementation in one place. No other project needs to know about the module's internals.

public sealed class CatalogModule : IModule
{
    public IServiceCollection Register(IServiceCollection services, IConfiguration configuration)
    {
        services.AddDbContext<CatalogDbContext>(options =>
            options.UseNpgsql(configuration.GetConnectionString("Postgres")));

        services.AddSingleton<CatalogMapper>();
        services.AddScoped<IProductRepository, ProductRepository>();
        services.AddScoped<IProductService, ProductService>();
        services.AddScoped<ICatalogModule, CatalogModuleApi>();
        return services;
    }
}

Note: CatalogMapper is registered as a singleton because it is a Mapperly source-generated class — it holds no mutable state and is safe to share across requests.

The Mapperly mapper

CatalogMapper is a source-generated, zero-reflection mapper from Riok.Mapperly. The compiler generates the mapping implementations at build time — no runtime reflection, no magic strings.

Application

CatalogMapper

src/Modules/Catalog/Kheprx.BaseBackend.Catalog.Application/Mappings/CatalogMapper.cs
[Mapper]
public partial class CatalogMapper
{
    public partial ProductDto ToDto(Product product);
    public partial IReadOnlyList<ProductDto> ToDtoList(IReadOnlyList<Product> products);
}

The [Mapper] attribute (from Riok.Mapperly.Abstractions) triggers source generation. The partial keyword lets the compiler fill in the implementations. Property names are matched by convention — if names differ, use [MapProperty].

Add a new module

Use the Catalog module as the template. Replace Catalog with your new module name throughout.

  1. Create the four projects under src/Modules/<Name>/ Run dotnet new classlib four times for Kheprx.BaseBackend.<Name>.Domain, .Application, .Infrastructure, and .Contracts. Add them to the solution with dotnet sln add. Wire project references following the dependency table: Domain ← Application ← Infrastructure, Contracts ← Infrastructure.
  2. Implement the Domain layer Add your aggregate root entity extending BaseEntity from SharedKernel. Add domain exception(s) extending DomainException. Keep this project free of NuGet dependencies beyond SharedKernel.
  3. Implement the Application layer Add DTOs (request/response records), a FluentValidation validator per request type, a [Mapper]-annotated Mapperly mapper class, and a service interface (e.g. I<Name>Service).
  4. Add the Contracts layer Define the public module interface (e.g. I<Name>Module) that the host or other modules may use. Keep it thin — only methods other assemblies genuinely need.
  5. Implement the Infrastructure layer Create a module-scoped DbContext, Fluent API entity configuration, repository implementing the interface from Application, service implementing the service interface, <Name>ModuleApi implementing the Contracts interface, and class <Name>Module : IModule that wires all of the above into DI.
  6. Reference Infrastructure from the host Add a project reference from Kheprx.BaseBackend.Api to Kheprx.BaseBackend.<Name>.Infrastructure so that AddModules() can discover and load the new IModule at runtime.
  7. Add an EF Core migration Run dotnet ef migrations add Initial<Name> --project Kheprx.BaseBackend.<Name>.Infrastructure --startup-project Kheprx.BaseBackend.Api. Commit the generated migration files. Apply with dotnet ef database update.
  8. Add unit and architecture test coverage Create tests/Kheprx.BaseBackend.<Name>.UnitTests/ mirroring the Catalog unit tests. The existing Kheprx.BaseBackend.ArchitectureTests will automatically pick up the new module's assemblies — confirm the boundary and convention tests still pass.
  9. Run dotnet test Confirm all tests pass: dotnet test Kheprx.BaseBackend.sln. A green build proves the new module satisfies all dependency rules and the solution is still warning-clean (TreatWarningsAsErrors=true).
