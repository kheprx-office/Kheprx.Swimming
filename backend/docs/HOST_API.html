Host / Api

Program.cs — the entry point

Kheprx.BaseBackend.Api/Program.cs

Builds and runs the ASP.NET Core application: configures Serilog, registers all modules and shared infrastructure, then activates the shared middleware pipeline.

using Kheprx.BaseBackend.Api.Extensions;
using Kheprx.BaseBackend.SharedKernel.Modules;
using Serilog;

var builder = WebApplication.CreateBuilder(args);

builder.Host.UseSerilog((context, loggerConfiguration) =>
    loggerConfiguration.ReadFrom.Configuration(context.Configuration));

builder.Services.AddModules(builder.Configuration);
builder.Services.AddSharedInfrastructure(builder.Configuration);

var app = builder.Build();
app.UseSharedPipeline(app.Environment);
app.Run();

What's happening here: AddModules (from Kheprx.BaseBackend.SharedKernel.Modules) discovers every IModule implementation and calls its Register method, wiring each module's own DI registrations. AddSharedInfrastructure registers controllers, FluentValidation, Swagger, and CORS. UseSharedPipeline builds the middleware stack — exception handling, Swagger UI, Serilog request logging, CORS, and controller routing — all in one call. This file is intentionally minimal; all heavy wiring lives in the Extensions.

BaseApiController — the controller base

Kheprx.BaseBackend.Api/Controllers/BaseApiController.cs

The abstract base class for all controllers: applies [ApiController] and a conventional api/[controller] route, and exposes the Accept-Language header as a protected helper.

using Microsoft.AspNetCore.Mvc;

namespace Kheprx.BaseBackend.Api.Controllers;

[ApiController]
[Route("api/[controller]")]
public abstract class BaseApiController : ControllerBase
{
    protected string AcceptLanguage => Request.Headers.AcceptLanguage.ToString();
}

What's happening here: [ApiController] enables automatic model-state validation (overridden here by ModelStateResponse), binding-source inference, and problem-details responses. Putting the route template and the attribute on the base keeps every derived controller consistent without repeating boilerplate. AcceptLanguage is a convenience accessor that concrete controllers can read when they need to tailor responses to the caller's locale.

ProductsController — the CRUD surface

Kheprx.BaseBackend.Api/Controllers/ProductsController.cs

Exposes the five standard product endpoints; delegates all logic to IProductService (an Application layer interface) and wraps every response in ApiResponse<T> (a SharedKernel type). Response messages come from static resource classes (e.g. ProductMessages, CommonMessages) that localize per AppLanguage.Current — Arabic today, English kept as the default arm.

using Kheprx.BaseBackend.Api.Controllers;
using Kheprx.BaseBackend.Catalog.Application.DTOs;
using Kheprx.BaseBackend.Catalog.Application.Resources;
using Kheprx.BaseBackend.Catalog.Application.Services.Interfaces;
using Kheprx.BaseBackend.SharedKernel.Resources;
using Kheprx.BaseBackend.SharedKernel.Responses;
using Microsoft.AspNetCore.Mvc;

namespace Kheprx.BaseBackend.Api.Controllers;

public sealed class ProductsController : BaseApiController
{
    private readonly IProductService _service;

    public ProductsController(IProductService service) => _service = service;

    [HttpGet]
    public async Task<ActionResult<ApiResponse<IReadOnlyList<ProductDto>>>> GetAll(CancellationToken ct)
        => Ok(ApiResponse<IReadOnlyList<ProductDto>>.Success(
            ProductMessages.Success.ProductsListed(AppLanguage.Current), await _service.GetAllAsync(ct)));

    [HttpGet("{id:int}")]
    public async Task<ActionResult<ApiResponse<ProductDto>>> GetById(int id, CancellationToken ct)
    {
        var product = await _service.GetByIdAsync(id, ct);
        return product is null
            ? NotFound(ApiResponse<ProductDto>.Failure(ProductMessages.Errors.ProductNotFound(AppLanguage.Current), "PRODUCT_NOT_FOUND"))
            : Ok(ApiResponse<ProductDto>.Success(ProductMessages.Success.ProductRetrieved(AppLanguage.Current), product));
    }

    [HttpPost]
    public async Task<ActionResult<ApiResponse<ProductDto>>> Create(
        CreateProductRequest request, CancellationToken ct)
    {
        var product = await _service.CreateAsync(request, ct);
        return CreatedAtAction(nameof(GetById), new { id = product.Id },
            ApiResponse<ProductDto>.Success(ProductMessages.Success.ProductCreated(AppLanguage.Current), product));
    }

    [HttpPut("{id:int}")]
    public async Task<ActionResult<ApiResponse<ProductDto>>> Update(
        int id, UpdateProductRequest request, CancellationToken ct)
    {
        var product = await _service.UpdateAsync(id, request, ct);
        return product is null
            ? NotFound(ApiResponse<ProductDto>.Failure(ProductMessages.Errors.ProductNotFound(AppLanguage.Current), "PRODUCT_NOT_FOUND"))
            : Ok(ApiResponse<ProductDto>.Success(ProductMessages.Success.ProductUpdated(AppLanguage.Current), product));
    }

    [HttpDelete("{id:int}")]
    public async Task<ActionResult<ApiResponse<object>>> Delete(int id, CancellationToken ct)
    {
        var deleted = await _service.DeleteAsync(id, ct);
        return deleted
            ? Ok(ApiResponse<object>.Success(ProductMessages.Success.ProductDeleted(AppLanguage.Current), null))
            : NotFound(ApiResponse<object>.Failure(ProductMessages.Errors.ProductNotFound(AppLanguage.Current), "PRODUCT_NOT_FOUND"));
    }
}

What's happening here: the controller only knows about the Application interface IProductService — it never touches a repository or database directly. Every action returns ApiResponse<T> from SharedKernel, giving clients a uniform envelope (success flag, message, data, error code) regardless of which endpoint they hit. CreatedAtAction on the POST generates the Location header pointing to GetById, following REST conventions.

ValidationFilter — pre-action FluentValidation

Kheprx.BaseBackend.Api/Filters/ValidationFilter.cs

An IAsyncActionFilter that resolves a FluentValidation IValidator<T> for each action argument and short-circuits the pipeline with a 400 if validation fails — before the action method is ever called.

using Kheprx.BaseBackend.SharedKernel.Responses;
using Kheprx.BaseBackend.SharedKernel.Resources;
using FluentValidation;
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Filters;

namespace Kheprx.BaseBackend.Api.Filters;

public sealed class ValidationFilter : IAsyncActionFilter
{
    private readonly IServiceProvider _services;

    public ValidationFilter(IServiceProvider services) => _services = services;

    public async Task OnActionExecutionAsync(ActionExecutingContext context, ActionExecutionDelegate next)
    {
        foreach (var argument in context.ActionArguments.Values)
        {
            if (argument is null) continue;

            var validatorType = typeof(IValidator<>).MakeGenericType(argument.GetType());
            if (_services.GetService(validatorType) is IValidator validator)
            {
                var result = await validator.ValidateAsync(new ValidationContext<object>(argument));
                if (!result.IsValid)
                {
                    var errors = string.Join("; ", result.Errors.Select(e => e.ErrorMessage));
                    context.Result = new BadRequestObjectResult(
                        ApiResponse<object>.Failure(CommonMessages.Errors.ValidationFailed(AppLanguage.Current), errors));
                    return;
                }
            }
        }

        await next();
    }
}

What's happening here: the filter iterates every bound action argument, constructs the open generic IValidator<T> type at runtime, and asks the DI container for it. If a validator is registered (e.g. CreateProductRequestValidator in the Catalog Application layer), it runs asynchronously against the argument. On failure it writes a BadRequestObjectResult wrapping ApiResponse<object>.Failure and returns — next() is never called so the controller action is skipped entirely. See Validation for the full flow.

ExceptionHandlingMiddleware — global error catcher

Kheprx.BaseBackend.Api/Middlewares/ExceptionHandlingMiddleware.cs

Wraps the entire request pipeline; catches DomainException and turns it into a 400, catches all other exceptions and turns them into a 500 — both as structured ApiResponse JSON.

using Kheprx.BaseBackend.SharedKernel.Domain;
using Kheprx.BaseBackend.SharedKernel.Responses;

namespace Kheprx.BaseBackend.Api.Middlewares;

public sealed class ExceptionHandlingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<ExceptionHandlingMiddleware> _logger;

    public ExceptionHandlingMiddleware(RequestDelegate next, ILogger<ExceptionHandlingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (DomainException ex)
        {
            _logger.LogWarning(ex, "Domain rule violated");
            await WriteAsync(context, StatusCodes.Status400BadRequest, ex.Message, "DOMAIN_RULE_VIOLATION");
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Unhandled exception");
            await WriteAsync(context, StatusCodes.Status500InternalServerError,
                "An unexpected error occurred.", "SERVER_ERROR");
        }
    }

    private static Task WriteAsync(HttpContext context, int statusCode, string message, string error)
    {
        context.Response.StatusCode = statusCode;
        context.Response.ContentType = "application/json";
        return context.Response.WriteAsJsonAsync(ApiResponse<object>.Failure(message, error));
    }
}

What's happening here: the middleware sits at the very top of the pipeline (registered first in UseSharedPipeline), so it catches exceptions that bubble up from every layer below — including domain invariant violations thrown deep inside the Application or Domain. DomainException is a SharedKernel base class; throwing a subclass like InvalidProductException in Domain automatically results in a clean 400 here, with the domain's own message surfaced to the caller. All other exceptions are logged at Error level and returned as a generic 500 so internal details are never leaked.

ServiceCollectionExtensions — DI wiring

Kheprx.BaseBackend.Api/Extensions/ServiceCollectionExtensions.cs

Registers controllers (with ValidationFilter globally), configures camelCase JSON, overrides the model-state response factory, adds Swagger, scans all Kheprx.BaseBackend.* assemblies for FluentValidation validators, and adds a permissive CORS policy.

using System.Reflection;
using System.Text.Json;
using Kheprx.BaseBackend.Api.Filters;
using Kheprx.BaseBackend.Api.Validation;
using FluentValidation;
using Microsoft.AspNetCore.Mvc;
using Microsoft.Extensions.DependencyInjection;

namespace Kheprx.BaseBackend.Api.Extensions;

public static class ServiceCollectionExtensions
{
    public static IServiceCollection AddSharedInfrastructure(
        this IServiceCollection services, IConfiguration configuration)
    {
        var moduleAssemblies = AppDomain.CurrentDomain.GetAssemblies()
            .Where(a => a.GetName().Name?.StartsWith("Kheprx.BaseBackend.", StringComparison.Ordinal) == true)
            .ToArray();

        services.AddControllers(options => options.Filters.Add<ValidationFilter>())
            .AddJsonOptions(options =>
                options.JsonSerializerOptions.PropertyNamingPolicy = JsonNamingPolicy.CamelCase)
            .ConfigureApiBehaviorOptions(options =>
                options.InvalidModelStateResponseFactory = context =>
                    new BadRequestObjectResult(ModelStateResponse.From(context.ModelState)));

        services.AddEndpointsApiExplorer();
        services.AddSwaggerGen();

        services.AddValidatorsFromAssemblies(moduleAssemblies, includeInternalTypes: true);

        services.AddCors(options => options.AddPolicy("AllowAll",
            policy => policy.AllowAnyOrigin().AllowAnyHeader().AllowAnyMethod()));

        return services;
    }
}

What's happening here: options.Filters.Add<ValidationFilter>() registers the filter globally so every controller action gets FluentValidation automatically. The InvalidModelStateResponseFactory override replaces ASP.NET's default ValidationProblemDetails response with the project's own ApiResponse envelope via ModelStateResponse.From, keeping the response shape consistent whether the error came from model binding or from FluentValidation. The assembly scan collects validators from every Kheprx.BaseBackend.* project so validators defined in module Application layers are automatically discovered.

ApplicationBuilderExtensions — pipeline wiring

Kheprx.BaseBackend.Api/Extensions/ApplicationBuilderExtensions.cs

Builds the ASP.NET Core middleware pipeline in a single extension method: exception handling first, then conditional Swagger, Serilog request logging, CORS, and controller routing.

using Kheprx.BaseBackend.Api.Middlewares;
using Serilog;

namespace Kheprx.BaseBackend.Api.Extensions;

public static class ApplicationBuilderExtensions
{
    public static WebApplication UseSharedPipeline(this WebApplication app, IWebHostEnvironment environment)
    {
        app.UseMiddleware<ExceptionHandlingMiddleware>();

        if (environment.IsDevelopment())
        {
            app.UseSwagger();
            app.UseSwaggerUI();
        }

        app.UseSerilogRequestLogging();
        app.UseCors("AllowAll");
        app.MapControllers();
        return app;
    }
}

What's happening here: middleware order matters — ExceptionHandlingMiddleware is registered first so it wraps everything that follows. Swagger UI is gated behind IsDevelopment() so it is never exposed in production. UseSerilogRequestLogging() replaces the default Microsoft request logs with structured Serilog entries. MapControllers() wires all controller action routes. Program.cs calls this method as app.UseSharedPipeline(app.Environment), keeping the entry point minimal.

ModelStateResponse — model-binding error shaper

Kheprx.BaseBackend.Api/Validation/ModelStateResponse.cs

A static helper that converts ASP.NET Core's ModelStateDictionary (populated during model binding) into the project's standard ApiResponse<object> envelope.

using Kheprx.BaseBackend.SharedKernel.Responses;
using Kheprx.BaseBackend.SharedKernel.Resources;
using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Kheprx.BaseBackend.Api.Validation;

public static class ModelStateResponse
{
    public static ApiResponse<object> From(ModelStateDictionary modelState)
    {
        var errors = string.Join("; ", modelState.Values
            .SelectMany(entry => entry.Errors)
            .Select(error => error.ErrorMessage)
            .Where(message => !string.IsNullOrWhiteSpace(message)));

        if (string.IsNullOrWhiteSpace(errors))
            errors = CommonMessages.Errors.ValidationFallback(AppLanguage.Current);

        return ApiResponse<object>.Failure(CommonMessages.Errors.ValidationFailed(AppLanguage.Current), errors);
    }
}

What's happening here: when ASP.NET Core's model binder rejects a request (e.g. a required field is missing or a value cannot be parsed), it populates ModelStateDictionary and the InvalidModelStateResponseFactory in ServiceCollectionExtensions calls this method. All error messages are flattened into a semicolon-separated string and wrapped in ApiResponse<object>.Failure — the same shape that ValidationFilter and ExceptionHandlingMiddleware produce, so clients receive a consistent error envelope regardless of where in the pipeline the rejection occurred. See Validation for how all three error paths relate.

In simple words: Kheprx.BaseBackend.Api is the only project that knows about the web. Program.cs wires every module and service together at startup. The controllers translate HTTP calls into Application service calls and never touch the database directly. Three independent guards protect every request: ModelStateResponse catches bad binding, ValidationFilter catches business-rule input errors, and ExceptionHandlingMiddleware catches anything that still escapes into an exception — all producing the same ApiResponse shape.
