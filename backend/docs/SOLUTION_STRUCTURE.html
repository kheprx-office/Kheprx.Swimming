Host project

Host / Api

Kheprx.BaseBackend.Api/

Kheprx.BaseBackend.Api/Kheprx.BaseBackend.Api.csproj

The single deployable ASP.NET Core host. Program.cs calls AddModules() (from ServiceCollectionExtensions) which discovers and registers every IModule implementation at startup. The pipeline is assembled by ApplicationBuilderExtensions. Controllers live here and depend on their own module's Application layer (e.g. IProductService, ProductDto) and SharedKernel (ApiResponse<T>). The .Contracts project is the narrow surface that other modules consume, not the host. ValidationFilter runs FluentValidation before action methods; ExceptionHandlingMiddleware converts domain exceptions to structured error responses.

SharedKernel

SharedKernel

Kheprx.BaseBackend.SharedKernel/

src/SharedKernel/Kheprx.BaseBackend.SharedKernel/

Provides building blocks that every module needs: BaseEntity (abstract aggregate root with int Id, CreatedAt, and UpdatedAt), DomainException (base for all domain errors), IModule (the registration contract), ModuleRegistration (assembly scanner used in AddModules()), and the ApiResponse<T> / BaseApiResponse envelope for consistent HTTP responses. You add to SharedKernel only when a concept is genuinely cross-cutting.

Mental model

The host (Kheprx.BaseBackend.Api) is the only deployable artefact — it sits at the root and discovers modules at startup via the IModule interface defined in SharedKernel. Shared abstractions that any module might need (base classes, response envelopes, the module registration mechanism) live in SharedKernel under src/SharedKernel/, keeping them clearly separated from module-specific code. Each module lives in its own folder under src/Modules/ and is split into four projects that enforce a strict inside-out dependency order: Domain has no external dependencies, Application depends only on Domain, Infrastructure implements both, and Contracts exposes only what the outside world needs to know. The test projects under tests/ mirror this structure: unit tests target individual modules, while the architecture tests act as a safety net that prevents dependency rule violations from ever reaching the main branch.
